# 데스크톱 검증 워크벤치 설계

## 목적

DART 검증보고서를 모바일 보고서가 아닌 데스크톱 검토 웹앱으로 재구성한다.
사용자는 왼쪽에서 재무제표 본문과 각 주석을 선택하고, 중앙에서 원문 표를 읽으며,
표 내부 산술 검증은 대상 셀의 굵은 테두리로 확인한다. 재무제표-주석,
현금흐름표-주석, 주석-주석처럼 서로 다른 표를 비교하는 대사는 오른쪽 드로워에서
금액, 결과, 판단 근거, 필요한 행동과 원문 위치를 확인한다.

## 성공 기준

- 데스크톱 첫 화면이 `왼쪽 원문 탐색 / 중앙 원문 표 / 오른쪽 대사 드로워`로 구성된다.
- 왼쪽 탐색은 현재와 같이 `재무제표 본문`과 `각 주석`을 구분한다.
- 중앙 표는 원본의 `rowspan`, `colspan`, 다단 머리글을 보존한다.
- 계산 엔진이 사용하는 정규화 행렬과 화면이 사용하는 원본 표 레이아웃을 분리한다.
- 합계, 소계, 총계, 증감표, 이익잉여금 처분 산식처럼 한 표 안에서 끝나는 검증은
  정확한 대상 셀의 굵은 테두리로 표시한다.
- 서로 다른 표를 비교하는 대사는 우측 드로워에만 표시한다.
- 검증 결과의 상태, 금액, 차이, 내부 ID와 순서는 바꾸지 않는다.
- `LOCAL VERIFY`, `PyOdide`, 스택 트레이스, 내부 검증 코드가 사용자 화면에 보이지 않는다.
- React나 Next.js를 추가하지 않고 현재 Python 렌더러와 가벼운 JavaScript로 구현한다.

## 화면 구조

### 상단 바

- 보고서명, 회사명, 보고기간
- `검토 필요`, `원문 확인 필요` 건수
- 보고서 내보내기
- 엔진 로딩 상태나 런타임 이름은 표시하지 않는다.

### 왼쪽 원문 탐색

`재무제표 본문` 아래에 재무상태표, 손익계산서, 포괄손익계산서, 자본변동표,
현금흐름표, 이익잉여금처분계산서를 공시 순서대로 표시한다. `각 주석` 아래에는
주석 번호와 주석명을 공시 순서대로 표시한다.

각 항목의 배지는 해당 섹션에 연결된 검증 중 가장 중요한 상태만 보여준다.

- 일치만 존재: 녹색 완료 배지
- 미해소 차이 존재: 주황색 확인 필요 건수
- 자동 확정 불가 존재: 회색 원문 확인 건수
- 차이 원인이 설명됨: 청록색 설명됨 배지
- 검증하지 않음: 배지 없음
- 검증이 연결되지 않음: 배지 없음

대시보드, 진행상황, 검증 범례는 기본 탐색 항목에서 제거한다. 필요한 상태 집계는
상단 바와 탐색 배지로 축약한다.

### 중앙 원문 표

선택한 재무제표 또는 주석의 제목, 단위, 원문 표를 표시한다. 표는 DART 원본의
병합 구조와 머리글 위계를 보존한다. 원문에 여러 표가 있으면 공시 순서대로 이어서
표시한다.

행 전체에 검증 상태를 칠하지 않는다. 검증 결과는 검증이 실제로 계산한 대상 셀에만
적용한다.

- 일치: 3px 녹색 테두리
- 미해소 차이: 3px 주황색 테두리
- 자동 확정 불가: 2px 회색 점선
- 차이 원인이 설명됨: 3px 청록색 테두리
- 검증하지 않음: 테두리 없음
- 한 셀에 여러 검증이 연결됨: 가장 중요한 상태의 테두리와 검증 건수 표시

여러 검증의 표시 우선순위는 `미해소 차이 > 자동 확정 불가 > 차이 원인 설명됨 > 일치`
순서다. 이 우선순위는 표시만 결정하며 개별 검증 상태를 합치거나 바꾸지 않는다.

셀에 마우스를 올리거나 키보드로 초점을 이동하면 검증명, 계산식, 기준 금액,
표시 금액, 차이를 작은 설명 상자로 보여준다. 표 내부 검증은 우측 대사 드로워를
강제로 열지 않는다.

### 오른쪽 대사 드로워

중앙 표에서 다른 표와 연결된 검증 셀 또는 대사 배지를 선택하면 드로워를 연다.
드로워는 다음 순서로 표시한다.

1. 대사 항목과 결과
2. 기준 표 금액과 비교 표 금액
3. 차이
4. 판단 근거
5. 다음에 확인할 내용
6. 양쪽 원문 위치

동일한 셀에 대사가 여러 건 연결되면 `확인 필요`, `일치` 탭으로 나눈다. 드로워의
원문 위치를 선택하면 중앙 화면이 해당 재무제표 또는 주석으로 이동하고 정확한 셀을
잠시 강조한다.

`담당자 확인 요청`, `검토 근거 남기기`는 현재 단계에서 실제 저장 기능으로 만들지
않는다. 백엔드에 검토 상태 저장 계약이 생기기 전까지는 `다음에 확인할 내용`이라는
안내만 제공한다.

## 백엔드 표 구조 계약

### 계산용 정규화 표

현재 `ReportTable.rows`는 병합 셀을 계산 가능한 직사각형 행렬로 펼친다. 이 값은
footing, reconciliation, taxonomy, amount locator가 사용하므로 변경하지 않는다.
기존 행 수, 열 수, 문자열, `row_acodes`, 단위 정보도 그대로 유지한다.

### 표시용 원본 레이아웃

파서가 표를 읽을 때 계산용 행렬과 별도로 원본 셀 레이아웃을 보존한다. 표시용 셀은
최소한 다음 정보를 가진다.

- 셀 텍스트
- 정규화 행렬에서 시작하는 행·열 좌표
- `rowspan`, `colspan`
- `th` 또는 `td` 구분
- 원문 줄 위치
- acode

이 메타데이터는 `ReportTable`의 선택적 표시 필드로 추가한다. 기존 테스트나 호출자가
직접 만든 `ReportTable`처럼 표시 메타데이터가 없으면 현재 정규화 행렬을 병합 없이
렌더링한다. 새 필드는 기본값을 갖는 마지막 필드로 추가해 기존 위치 인자 생성 코드도
깨지지 않게 한다.

병합 셀 안의 정규화 좌표가 검증 근거로 지정되면, 표시 레이아웃은 그 좌표를 포함하는
원본 셀을 찾아 셀 전체에 테두리를 적용한다. 반복 문자열을 비교해 병합을 추측하지
않는다.

### 검증 셀 주석

`report_frame`은 보고서와 `CheckResult` 목록을 받아 표별 `CellAnnotation`을 만든다.
각 주석은 다음 정보를 가진다.

- 표와 대상 셀 좌표
- 화면 표시 검증명
- 상태
- 기준 금액, 표시 금액, 차이, 허용 차이
- 표 내부 검증 또는 표 사이 대사 구분
- 연결된 원문 위치

대상 셀은 검증 근거의 명시적 역할을 우선 사용한다.

- `total_check`: 합계·소계·총계 표시 셀
- `note_rollforward_check`: `ending` 역할의 기말 셀
- `note_layout_formula_check`: 발견된 산식의 목표 역할 셀
- `appropriation_formula_check`: 처분 산식의 결과 셀

현재 일부 산식 검증이 목표 역할을 근거에 명시하지 않는 경우, 검증 결과의 숫자와
판정을 바꾸지 않고 근거 역할만 보강한다. 화면에서 금액이나 라벨을 비교해 목표 셀을
추측하지 않는다. 역할 보강 전후에 `status`, `expected`, `actual`, `difference`,
`check_id`, 결과 순서가 동일함을 회귀 테스트로 고정한다.

### 표 내부 검증과 표 사이 대사 분기

표 내부 셀 테두리 대상은 다음과 같다.

- `total_check`
- `note_rollforward_check`
- `note_layout_formula_check`
- `appropriation_formula_check`

우측 드로워 대상은 다음과 같다.

- 재무제표 본문과 주석을 비교하는 대사
- 현금흐름표와 주석을 비교하는 대사
- 서로 다른 주석을 비교하는 대사
- 전기 공시와 당기 공시를 비교하는 대사
- 재무제표 본문끼리 비교하는 교차 검증

분기는 검증 유형 문자열을 화면 코드에서 새로 나열하지 않고 `report_frame`의 기존
그룹·레이어 레지스트리를 확장해 한 곳에서 결정한다.

## 데이터 흐름

```text
DART HTML
  -> HTML 표 파서
     -> 계산용 정규화 행렬
     -> 표시용 원본 셀 레이아웃
  -> 기존 검증 파이프라인
     -> CheckResult / CheckEvidence
  -> report_frame
     -> 왼쪽 탐색 모델
     -> 표별 CellAnnotation
     -> 우측 DrawerItem
  -> 공통 HTML 렌더러
  -> 독립 HTML 보고서와 verify-app에 동일하게 표시
```

verify-app은 별도 결과 화면을 만들지 않고 기존처럼 공통 HTML 렌더러 결과를 사용한다.
업로드 셸은 파일 선택과 실행 상태만 담당한다.

## 업로드 웹앱 화면

`static/dart-verify`는 데스크톱 단일 화면으로 단순화한다.

- 사용자 문구: `DART 원문 선택`, `검증 준비 중`, `검증 중`, `검증 완료`, `파일 확인 필요`
- 제거 문구: `LOCAL VERIFY`, `엔진`, `PyOdide`, 패키지 경로, JavaScript/Python 오류 스택
- 기술 오류는 콘솔에만 남기고 화면에는 사용자가 할 수 있는 조치만 표시한다.
- 검증 완료 후 입력 패널은 축소하고 결과 워크벤치에 화면 너비를 우선 배정한다.

## React와 Next.js 경계

이번 범위의 상태는 선택한 섹션, 열린 드로워, 강조 셀, 필터 정도이며 저장되지 않는다.
현재 Python 생성 HTML과 가벼운 JavaScript로 충분하다.

Vite React는 다중 보고서, 저장된 검토 상태, 담당자 배정, 검토 메모 저장,
교차 보고서 탐색이 실제 요구사항이 될 때 도입한다. Next.js는 인증, 서버 업로드,
데이터베이스, 공유 작업공간이 필요할 때만 검토한다.

## 예외 처리

- 표시 레이아웃 없음: 정규화 행렬을 병합 없이 표시
- 근거 좌표가 병합 셀 내부: 해당 좌표를 포함하는 원본 셀에 테두리 적용
- 근거 좌표를 찾을 수 없음: 원시 경로를 노출하지 않고 `원문 위치 확인 필요` 표시
- 한 셀에 여러 내부 검증: 가장 중요한 상태와 검증 건수 표시
- 드로워에 여러 대사: 확인 필요 항목을 먼저 정렬
- 원문 표가 지나치게 넓음: 중앙 영역에서 가로 스크롤 허용, 왼쪽 탐색과 드로워 고정
- 파서 실행 실패: 스택 트레이스 대신 지원 형식과 다시 선택할 행동만 안내

## 접근성

- 셀 상태를 색상만으로 전달하지 않고 `합계 일치`, `합계 확인`, `원문 확인` 문구를
  툴팁과 접근성 이름에 포함한다.
- 검증 셀은 키보드로 초점을 받을 수 있어야 한다.
- 드로워는 열릴 때 제목으로 초점을 이동하고 닫으면 원래 셀로 초점을 돌린다.
- 테이블 머리글은 원본 `th` 정보를 사용해 행·열 관계를 유지한다.
- 드로워 닫기와 원문 이동은 실제 버튼으로 렌더링한다.

## 테스트 전략

### 파서 계약

- `rowspan`, `colspan`, 다단 머리글 fixture에서 원본 셀 범위를 보존한다.
- 같은 fixture의 `ReportTable.rows`와 `row_acodes`는 변경 전과 동일해야 한다.
- 선행 단위 행을 제거해도 표시 좌표와 정규화 좌표가 일치해야 한다.

### 검증 불변성

- 변경 전후 `CheckResult`의 상태, 기준 금액, 표시 금액, 차이, ID, 순서를 비교한다.
- 소계·총계·증감표 회귀 fixture의 기존 검증 건수와 판정을 유지한다.

### 화면 계약

- 병합 셀이 실제 `rowspan`, `colspan`으로 렌더링된다.
- 네 종류의 표 내부 검증이 정확한 목표 셀에 테두리를 적용한다.
- 일치, 미해소 차이, 자동 확정 불가, 차이 원인 설명됨의 테두리와 접근성 문구를
  확인하고 `검증하지 않음`에는 테두리가 생기지 않는지 확인한다.
- 표 사이 대사는 셀 내부 상세가 아니라 우측 드로워에 표시된다.
- 왼쪽 탐색이 재무제표 본문과 각 주석만 표시한다.
- verify-app과 독립 HTML이 같은 워크벤치 마크업을 사용한다.
- 사용자 HTML에 시스템 용어와 오류 스택이 남지 않는다.

### 시각 QA

- 1440x900과 1600x1000 데스크톱 화면만 검증한다.
- 병합 머리글, 긴 주석명, 넓은 표, 여러 검증이 연결된 셀을 확인한다.
- 좌측 탐색, 중앙 가로 스크롤, 우측 드로워가 서로 겹치지 않는지 확인한다.
- 모바일 레이아웃은 이번 완료 기준에 포함하지 않는다.
