# 검증보고서 UI 전체 보강 설계

## 목적

현재 SK이터닉스 실제 공시자료로 생성한 데스크톱 검증보고서를 기준으로,
검토자가 `무엇을 검증했는지`, `결과가 무엇인지`, `다음에 무엇을 해야 하는지`를
한 화면에서 빠르게 판단하도록 UI를 보강한다. 이번 단계는 기존 검증 결과와
원문 위치를 읽기 전용으로 보여주는 범위에 한정한다.

React, Next.js 또는 별도 프런트엔드 런타임은 추가하지 않는다. 현재 Python HTML
렌더러와 독립 실행 JavaScript를 유지해 DSD/XML/PDF 입력에서 생성되는 동일한
보고서 표면에 적용한다.

## 범위

### 이번 구현에 포함

- 연결/별도 범위와 재무제표/주석 페이지를 이동할 때 검토 문맥 초기화
- 상단 검토 현황의 의미와 동작 정리
- 재무제표-주석, 현금흐름표-주석, 주석-주석 대사 드로워의 정보 구조 통일
- 금액 검증과 주석번호 완전성 결론 분리
- 합계·소계 검증 셀의 명시적 표시와 미검증 상태 구분
- 넓은 주석 표의 가로 탐색과 머리글 가독성 개선
- 키보드 접근성과 포커스 이동 개선
- PDF에서 유입된 표시용 위치 문구의 불필요한 `0`, 줄바꿈 흔적 정리
- 독립 HTML과 verify-app 공통 렌더러의 회귀 테스트

### 이번 구현에서 제외

- 검토 완료, 보류, 메모의 저장
- 사용자별 검토 이력과 재접속 복원
- 인증, 서버 API, 데이터베이스
- 검증 계산식, 상태, 금액, 허용오차 또는 결과 순서 변경
- 모바일 화면
- React/Next.js 전환

## 핵심 원칙

1. Footing과 현금흐름표 대사는 별도 검증으로 유지한다.
2. 합계·소계 테두리는 기존 검증 결과의 명시적 대상 셀에만 표시한다.
3. 표시 문구를 정리해도 모든 중요 금액의 원문 위치는 내부 근거에 보존한다.
4. 화면에서 계정명이나 금액을 다시 추측해 새로운 검증 결과를 만들지 않는다.
5. 원문 확인이 필요한 불확실성은 숨기지 않고 사용자가 이해할 수 있는 문구로 표시한다.
6. 페이지 이동과 드로워 이동을 구분해 오래된 검토 결과가 새 원문 옆에 남지 않게 한다.

## 선택한 접근

기존 `report_html.py`의 서버 렌더링 마크업, CSS, 독립 JavaScript를 보강한다.
검증 데이터 계약은 유지하고 표시용 helper와 상태 속성만 확장한다.

CSS만 수정하는 접근은 잘못 유지되는 스크롤·드로워 문맥과 필터 동작을 해결하지
못한다. 프런트엔드 프레임워크 전환은 현재의 읽기 전용 상태에 비해 배포 복잡도가
크다. 따라서 현재 구조 안에서 마크업 계약과 상호작용을 명시적으로 고치는 방법을
사용한다.

## 화면 설계

### 1. 상단 검토 현황

상단은 동일한 모집단을 기준으로 `전체`, `일치`, `확인 필요`, `원문 확인 필요`를
표시한다. 숫자를 누르면 단순히 첫 결과를 여는 대신 해당 범주의 검토 결과만
드로워 탐색 대상으로 삼는다. 선택된 범주는 눌림 상태와 문구로 표시한다.

상단 현황과 드로워 범주 선택은 같은 필터 상태를 사용한다. 이전/다음 이동도 현재
선택한 범주 안에서만 순환한다. 범주를 다시 선택하거나 `전체`를 선택하면 전체
결과 탐색으로 돌아간다.

### 2. 연결/별도와 왼쪽 탐색

연결/별도 전환 시 해당 범위의 첫 재무제표를 활성화하고 중앙 원문을 맨 위로
이동한다. 기존 드로워는 닫고 새 범위명이 보조기기에 전달되도록 상태 영역을
갱신한다.

재무제표 또는 주석 목차를 직접 선택할 때도 중앙 원문을 맨 위로 이동하고 기존
드로워를 닫는다. 다만 드로워의 `주석 위치` 버튼으로 이동할 때는 대상 페이지를
연 뒤 해당 셀 또는 행으로 이동하고 잠시 강조한다.

긴 목차명은 한 줄 말줄임을 유지하되 전체 제목을 `title`과 접근 가능한 이름으로
제공한다. 사이드바 앞에는 `본문으로 건너뛰기` 링크를 둔다.

### 3. 중앙 원문과 합계 표시

기존 원문 병합 구조, 행 유형, 금액, 단위를 그대로 렌더링한다. 검증 결과가 있는
합계·소계·총계 목표 셀에는 현재 상태에 맞는 굵은 테두리를 표시한다.

- 일치: 굵은 초록색 테두리와 `합계 일치` 설명
- 차이: 굵은 주황색 테두리와 `합계 확인 필요` 설명
- 원문 해석 필요: 회색 점선과 `합계 원문 확인 필요` 설명
- 명시적 합계 행이지만 연결된 검증 결과 없음: 행 옆에 `검증 결과 없음` 표시
- 일반 행 또는 검증 대상이 아님: 추가 표시 없음

`검증 결과 없음`은 새로운 계산 결과가 아니라, 표시용 행 유형은 합계인데 해당
셀에 기존 검증 주석이 연결되지 않은 경우만 나타낸다. 이를 통해 검증 완료와
미수행을 혼동하지 않게 한다.

여러 검증이 한 셀에 연결되면 `합계 검증 N건`처럼 의미가 있는 작은 배지를 유지하고,
숫자만 단독으로 표시하지 않는다.

### 4. 넓은 주석 표

표는 중앙 영역 안에서만 가로 스크롤한다. 첫 설명 열을 고정하고, 가능한 경우 다단
머리글을 위쪽에 고정한다. 머리글에는 `word-break: keep-all`과 열별 최소 너비를
적용해 한글 단어가 임의 위치에서 나뉘지 않게 한다.

가로 스크롤이 가능한 표는 오른쪽 가장자리 그림자와 `가로로 이동하여 전체 금액
확인` 안내를 보여준다. 사용자가 끝까지 이동하면 그림자는 사라진다. 이 표시는
JavaScript가 비활성화되어도 표 읽기를 방해하지 않는다.

### 5. 우측 검토 드로워

드로워 제목은 검증 유형이 아니라 사용자가 선택한 계정 또는 현금흐름 항목명이다.
그 아래에 검증 결론을 나눠 표시한다.

- 금액과 주석번호가 모두 문제없음: `금액 일치 · 주석번호 확인 완료`
- 금액은 일치하고 주석번호 누락 후보가 있음: `금액 일치 · 주석번호 확인 필요`
- 금액 차이가 있음: `금액 차이 확인 필요`
- 원문 후보가 모호함: `원문 확인 필요`

드로워 내용은 다음 순서만 사용한다.

1. 결과
2. 대사 금액
3. 주석 위치
4. 필요한 행동

재무제표 행을 선택해 연 드로워에서는 `재무제표 해당 셀`과 `원문 위치` 섹션을
표시하지 않는다. 주석 위치는 실제 대사에 사용한 주석을 `실재성 · 주석 N`으로
초록색 표시하고, 재무제표 주석번호에서 빠진 후보를 `완전성 누락 · 주석 N`으로
빨간색 표시한다.

금액 이름은 출처를 직접 나타낸다.

- 재무제표-주석: `재무제표 금액`, `주석 N 금액`, `차이`
- 현금흐름표-주석: `현금흐름표 금액`, `주석 N 변동금액`, `차이`
- 주석-주석: 각 주석번호 또는 주석명을 포함한 금액명, `차이`

필요한 행동이 없으면 `추가로 확인할 사항이 없습니다.` 한 줄만 표시한다. 확인이
필요하면 사용자가 실제로 할 수 있는 한 가지 행동을 우선 표시한다.

### 6. 표시용 원문 문구 정리

위치 문자열은 원본 근거를 바꾸지 않고 화면 표시용 복사본만 정리한다.

- 단독 `0`, 빈 라벨, 중복 구분자 제거
- PDF 줄바꿈에서 생긴 연속 공백 정리
- 계정명 내부의 정상적인 한글·숫자·기호 보존
- 원문 이동용 대상 ID와 source 문자열은 변경하지 않음

정리 결과가 비게 되면 추측한 문구를 만들지 않고 주석번호 또는 표 제목처럼 이미
보존된 명시적 위치명만 사용한다.

## 상호작용 상태 계약

독립 JavaScript는 다음 네 상태만 관리한다.

- 활성 보고서 범위
- 활성 원문 패널
- 활성 드로워 결과
- 활성 결과 범주 필터

`activatePanel(panelId, options)`는 직접 목차 이동과 근거 위치 이동을 구분한다.
기본값은 스크롤 상단 이동과 드로워 닫기다. 근거 이동만 `preserveDrawer`와
`targetId`를 전달해 드로워를 유지하고 정확한 원문을 강조한다.

드로워 결과 목록은 활성 보고서 범위와 결과 범주를 모두 만족하는 항목만 반환한다.
이전/다음, 현재 번호, 빈 결과 안내는 이 필터링된 목록을 동일하게 사용한다.

## 접근성

- 페이지 첫 요소로 `본문으로 건너뛰기` 링크 제공
- 활성 패널의 제목에 프로그래밍 방식으로 초점 이동
- 마우스 클릭에서는 불필요한 포커스 테두리를 줄이고 키보드에서는 명확한
  `:focus-visible` 테두리 제공
- 드로워가 열리면 제목으로 이동하고 닫히면 원래 선택 요소로 복귀
- 범위와 필터 변경은 `aria-live="polite"` 상태 영역으로 알림
- 상태는 색뿐 아니라 `일치`, `확인 필요`, `원문 확인 필요` 문구로 전달
- 검증 셀과 원문 이동 버튼에는 결과와 대상을 포함한 접근 가능한 이름 제공

## 데이터·검증 불변성

이번 변경 전후에 다음 값은 동일해야 한다.

- `CheckResult.status`
- `expected`, `actual`, `difference`, `tolerance`
- `check_id`, `check_type`, 결과 순서
- `CheckEvidence.source`, 역할과 원문 대상
- Footing 결과 수와 현금흐름 대사 결과 수

새로 추가하는 것은 표시용 제목, 결론 조합, 상태 필터 속성, 합계 미연결 안내뿐이다.

## 오류와 예외 처리

- 필터 범주에 결과가 없음: 드로워를 닫고 `해당 결과가 없습니다.`를 상태 영역에 알림
- 원문 이동 대상 없음: 드로워를 유지하고 `주석 위치를 자동으로 찾지 못했습니다.` 표시
- 표시용 항목명 없음: 내부 검증 유형 대신 이미 번역된 검증 표시명을 보조 제목으로 사용
- 합계 행 좌표와 주석 좌표 불일치: 테두리를 추측해 적용하지 않고 `검증 결과 없음` 유지
- JavaScript 비활성화: 원문 표와 모든 드로워 내용은 HTML에 남아 있으며 탐색 링크는
  기본 문서 구조를 해치지 않음

## 테스트 전략

### 렌더러 계약 테스트

- 상단 네 상태가 같은 모집단의 건수를 표시하는지 확인
- 드로워 항목에 범위, 결과 범주, 대상 계정명이 포함되는지 확인
- 재무제표 드로워에서 `원문 위치`, `재무제표 해당 셀`이 사라지는지 확인
- 복합 결론과 출처별 금액명이 정확히 렌더링되는지 확인
- 합계 검증 셀과 미연결 합계 행이 서로 다른 표시를 갖는지 확인
- 시스템 코드, 내부 검증 유형, PDF 단독 `0`이 사용자 문구에 남지 않는지 확인

### JavaScript 회귀 테스트

- 목차 이동 시 스크롤 상단, 드로워 닫기, 제목 포커스
- 범위 전환 시 첫 패널 활성화와 드로워 초기화
- 근거 위치 이동 시 드로워 유지와 대상 강조
- 상태 필터 적용 후 이전/다음이 같은 범주 안에서만 이동
- 결과가 없는 범주의 안전한 처리
- 가로 스크롤 그림자 상태 갱신

### 통합·시각 QA

- `uv run pytest` 기본 테스트
- SK이터닉스 실제 PDF 기반 보고서 재생성
- 1440×1000 데스크톱에서 연결/별도, 재무상태표, 현금흐름표, 넓은 주석,
  합계 셀, 누락 주석 드로워 확인
- 동일 뷰포트의 변경 전·후 화면을 나란히 비교
- 키보드만 사용해 본문 이동, 원문 선택, 드로워 열기/닫기, 범주 이동 확인
- 모바일 화면은 확인 대상에서 제외

## 예상 변경 영역

- `src/dart_footing_reconciler/report_html.py`
- `tests/test_report_html_new.py`
- `tests/test_report_html_cockpit.py`
- `tests/test_report_html_evidence.py`
- 필요하면 인라인 동작을 검증하는 별도 JavaScript 계약 테스트
- SK이터닉스 생성 보고서와 Playwright QA 산출물

파서, Footing 엔진, 현금흐름 대사 계산 모듈은 이번 설계의 기본 변경 대상이 아니다.
표시 계약에 필요한 근거가 실제로 누락된 경우에만 별도 실패 테스트를 작성하고 범위를
재평가한다.

## 후속 개발계획: 검토 작업 저장

이번 UI가 안정화된 뒤 별도 단계로 다음 기능을 설계한다.

1. 검증 결과별 `미검토 / 검토 완료 / 보류` 상태 저장
2. 검토 메모와 작성자·수정시각 기록
3. 보고서 재접속 시 사용자별 검토 상태 복원
4. 원문 파일 해시와 검증 실행 버전에 결합된 변경 이력
5. 재검증 시 이전 검토 결과의 승계 또는 재검토 정책
6. 인증·권한·API·데이터베이스 도입 여부 결정

이 단계가 실제로 시작되기 전까지 현재 보고서의 `필요한 행동`은 안내 문구이며,
저장되는 버튼처럼 보이게 만들지 않는다.

## 완료 기준

- 페이지와 범위를 바꿀 때 오래된 스크롤·드로워 문맥이 남지 않는다.
- 선택한 계정과 검증 결과, 대사 금액, 주석 위치, 후속 행동을 드로워에서 바로 읽을 수 있다.
- 금액 일치와 주석번호 확인 필요가 하나의 모호한 상태로 합쳐지지 않는다.
- 기존 검증이 연결된 합계 셀은 굵은 테두리와 텍스트 설명을 갖는다.
- 합계 행이지만 검증 결과가 없는 경우 사용자가 그 사실을 구분할 수 있다.
- 넓은 주석 표의 마지막 열까지 명확히 접근할 수 있다.
- 키보드로 핵심 검토 흐름을 완료할 수 있다.
- 기존 검증 결과와 원문 근거가 변경되지 않는다.
- React/Next.js와 백엔드 저장 기능을 추가하지 않는다.
