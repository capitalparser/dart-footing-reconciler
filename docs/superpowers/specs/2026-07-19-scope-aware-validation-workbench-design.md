# 범위 전환형 검증 워크벤치 설계

## 목적

첨부된 DSD/XML 또는 PDF 보고서 한 건만 검증하는 배포 흐름을 전제로, 하나의
검증보고서 화면에서 좌상단 `연결 / 별도` 범위를 전환한다. 선택한 범위의 재무제표,
주석, 검증 결과와 우측 드로워만 표시해 서로 다른 범위가 섞이지 않게 한다.

재무제표 본문과 주석에서는 사용자가 검증된 행 또는 셀을 바로 알아보고, 선택했을 때
`무엇을 무엇과 비교했는지`, `결과가 무엇인지`, `사용자가 무엇을 해야 하는지`를
우측 드로워에서 확인할 수 있어야 한다. 표 내부 합계 검증은 대상 셀의 굵은 테두리로,
표 사이 대사는 양쪽 원문 위치에서 같은 드로워 결과를 여는 방식으로 표시한다.

## 성공 기준

- 한 HTML 안에서 좌상단 `연결 / 별도` 선택기를 제공한다.
- 범위를 바꾸면 왼쪽 탐색, 중앙 표, 상단 건수, 셀 주석, 우측 드로워가 함께 바뀐다.
- 선택하지 않은 범위의 원문과 검증 결과는 화면 탐색과 드로워에서 접근되지 않는다.
- 한 범위만 존재하면 선택기는 숨기고 그 범위를 바로 표시한다.
- 재무제표의 대사 근거가 있는 계정 행은 행 전체를 키보드와 마우스로 선택할 수 있다.
- 행을 선택하면 우측 드로워에 연결된 검증을 중요도순으로 표시한다.
- 소계·합계·행 합계 목표 셀은 스크롤 끝에서도 보이는 굵은 안쪽 테두리를 가진다.
- 재무제표-주석과 주석-주석 대사는 모든 정확한 근거 셀에서 동일 결과를 연다.
- 현금흐름표 검증은 현금 증감, 자산 취득·처분, 차입·상환, 리스 상환과 비현금 조정을
  일반화된 규칙으로 다룬다.
- 사용자 화면에는 내부 검증 유형, 코드 ID, 파서·프레임워크 용어를 표시하지 않는다.
- React/Next.js를 추가하지 않고 현재 Python HTML 렌더러와 vanilla JavaScript를 유지한다.

## 입력 형식과 화면 계약

DSD/XML과 PDF는 입력·파싱 계층에서만 다르게 처리한다. 파서는 모두 `FullReport`,
`ReportSection`, `ReportTable`과 원문 위치를 만들고 검증 파이프라인은 이 공통 모델을
사용한다. 화면은 입력 형식에 따른 별도 컴포넌트를 두지 않는다.

PDF에서 구조나 라벨을 확정하지 못한 경우에도 `PDF 파싱 오류` 같은 시스템 문구 대신
`원문 확인 필요`와 구체적인 확인 행동을 표시한다. DSD/XML도 같은 상태 문구를 쓴다.

## 연결·별도 범위 전환

### 범위 판별

렌더러는 재무제표와 주석의 `scope`를 정규화해 `consolidated`, `separate` 가용 범위를
계산한다. 두 범위가 모두 있으면 `연결`을 기본값으로 한다. 하나만 있으면 해당 범위를
기본값으로 하고 선택기는 숨긴다. 범위가 없는 문서는 현재 단일 화면 동작을 유지한다.

### 렌더링 계약

문서 전체를 한 번에 렌더링하되 각 범위에 다음 속성을 부여한다.

- 범위 선택기: `data-report-scope="consolidated|separate"`
- 탐색 항목과 원문 패널: `data-scope-view="..."`
- 드로워 항목: 해당 검증의 `consolidation_basis` 또는 정확한 근거 섹션에서 결정한 범위
- 상단 상태 건수: 범위별로 미리 계산한 값

JavaScript는 선택 범위를 하나의 상태로 관리하고 모든 화면 영역을 동시에 갱신한다.
선택하지 않은 범위는 `hidden`과 `aria-hidden`으로 비활성화하며, 현재 범위의 첫 번째
원문 패널을 선택한다. 드로워가 열려 있으면 닫아 다른 범위 결과가 남지 않게 한다.

### 범위 귀속 우선순위

검증 결과의 범위는 다음 순서로 결정한다.

1. `CheckResult.consolidation_basis`
2. 정확한 evidence가 가리키는 재무제표·주석 섹션의 `scope`
3. 모든 근거가 같은 범위에 속할 때 그 범위
4. 결정 불가하면 공통 결과로 두되 한 범위 문서에서만 표시

두 범위에 걸친 것으로 잘못 귀속된 결과는 자동으로 복제하지 않는다. 내부 확인 대상으로
남기고 사용자 화면에는 다른 범위 결과를 섞지 않는다.

## 재무제표 계정 행과 우측 드로워

표 사이 대사가 연결된 정확한 금액 셀은 현재처럼 드로워 진입점이다. 여기에 재무제표
본문만 행 단위 진입점을 추가한다.

- 같은 행의 하나 이상 셀에 드로워 대사가 연결되면 행에 `검증 결과 N건` 표시를 둔다.
- 계정명 셀 또는 행을 선택하면 그 행에 연결된 드로워 결과의 첫 항목을 연다.
- 여러 결과가 있으면 `확인 필요`, `원문 확인 필요`, `차이 설명됨`, `일치` 순으로 정렬한다.
- 개별 금액 셀 선택은 그 셀에 직접 연결된 결과를 우선한다.
- 주석 표는 행 전체가 아니라 정확한 근거 셀만 드로워 진입점으로 유지한다.

드로워는 검증 그룹을 업무 용어로 표시한다.

- 재무제표-주석 대사
- 현금흐름표-주석 대사
- 주석 간 대사
- 재무제표 본문 대사
- 전기 보고서 대사

각 항목은 `검증 내용`, `비교 금액`, `결과`, `차이`, `판단 근거`, `확인할 행동`,
`양쪽 원문 위치` 순서로 표시한다.

## 표 내부 합계 표시

`total_check`, `note_rollforward_check`, `note_layout_formula_check`,
`appropriation_formula_check`의 목표 셀만 테두리 대상으로 유지한다. 계산에 사용된 구성
셀이나 행 전체를 합계 검증 대상으로 오인해 칠하지 않는다.

CSS `outline` 대신 셀 안쪽 `box-shadow: inset 0 0 0 3px ...`를 사용한다. 이는 가로
스크롤 컨테이너의 마지막 열에서도 잘리지 않는다. 상태별 색상과 점선 표현은 유지하되,
접근성 이름에 `합계 검증 일치`, `합계 검증 확인 필요`를 포함한다. 여러 검증이 같은
셀에 연결되면 건수 배지를 표시한다.

3-1 금융상품처럼 각 행 마지막 열이 행 합계인 표는 발견된 산식의 목표 셀마다 테두리를
표시한다. 소계 행도 명시적 목표 근거가 있을 때 같은 규칙을 적용한다.

## 양방향 표 사이 대사

드로워형 검증은 `CheckResult.evidence`의 모든 정확한 원문 좌표를 anchor로 사용한다.
따라서 재무제표-주석 대사는 재무제표 셀과 주석 셀 양쪽에서, 주석-주석 대사는 양쪽
주석 셀에서 같은 드로워 항목을 연다.

anchor가 표 단위에만 있거나 좌표를 찾을 수 없으면 임의 셀을 추측하지 않는다. 해당
검증은 범위별 `원문 확인 필요` 목록에 두고 `원문 위치를 자동으로 확정하지 못했습니다`
및 확인 행동을 표시한다.

왼쪽 탐색 배지는 상태만 보여주되, 선택한 섹션 상단에는 연결된 검증을
`합계 검증 / 재무제표-주석 / 현금흐름표-주석 / 주석 간 대사` 건수로 요약한다.

## 현금흐름표 검증 고도화

Footing과 현금흐름 대사는 계속 별도 검증으로 유지한다. 현금흐름표 내부 합계는 footing,
현금흐름표와 주석의 금액 비교는 reconciliation 계층이 담당한다.

### 검증 계열

1. 현금및현금성자산 기초 + 순증감 + 환율효과 = 기말 대사
2. 유형자산·무형자산·투자부동산 취득과 처분 대사
3. 단기·장기차입금과 사채의 차입·발행·상환·상환/발행 순액 대사
4. 리스부채 원금 상환 대사
5. 사업결합, 미지급 취득대금, 리스 비현금 취득, 대체, 환율변동 등 비현금 조정 설명

### 후보 선택

첫 번째 발견 금액을 사용하지 않는다. 현금흐름표 라인과 주석 증감 행 후보를 계정 계열,
movement role, 라벨 일치도, 기간 열, 원문 위치로 순위화한다. 동일 순위 후보가 여러 개면
`원문 확인 필요`로 보수적으로 멈춘다. 텍스트 필드, 날짜·이율·식별번호처럼 금액이 아닌
필드는 기존 필터를 유지한다.

강한 reconciliation 결과가 존재하면 단순 `cfs_note_match`는 중복 표시하지 않는다.
다만 강한 검증이 생성되지 않은 계열은 단순 규칙이 보조 검증으로 동작한다.

### 현금흐름표 UI

검증된 현금흐름표 라인은 계정 행 진입점을 가진다. 행 상단 또는 계정명 옆에
`주석과 일치`, `차이 설명됨`, `확인 필요`, `원문 확인 필요`를 표시하고, 선택하면
현금흐름표 금액과 주석 구성 금액 및 비현금 조정을 드로워에서 보여준다.

## 불변 조건

- 기존 `CheckResult`의 ID, 상태, 금액, 차이와 결과 순서를 화면 작업 때문에 변경하지 않는다.
- 현금흐름 검증 로직을 넓힐 때 새 결과에는 모든 material amount의 원문 위치를 보존한다.
- 라벨·후보 불확실성은 confidence/evidence 또는 `parse_uncertain`로 명시한다.
- 범위 필터링은 표시와 결과 귀속을 바꾸지만 서로 다른 범위 결과를 합산하지 않는다.
- 검증 코어는 MCP와 프론트엔드 프레임워크 없이 실행된다.
- 모바일 UI는 완료 기준에 포함하지 않는다.

## 테스트 전략

### 범위 전환

- 연결·별도 섹션이 있는 보고서에 선택기와 범위별 DOM 속성이 생성된다.
- 기본 연결 범위에서 별도 탐색·패널·드로워가 숨겨진다.
- 전환 시 상단 건수, 탐색, 패널, 드로워가 모두 같은 범위를 사용한다.
- 단일 범위 문서는 선택기를 숨긴다.

### 행과 드로워

- 재무제표 계정 행이 연결된 drawer index와 검증 건수를 가진다.
- 행 선택과 Enter/Space 입력이 드로워를 연다.
- 재무제표-주석과 주석-주석 결과가 모든 정확한 evidence 셀에 연결된다.
- 다른 범위의 드로워 항목은 열리지 않는다.

### 합계 표시

- 마지막 열의 `note_layout_formula_check` 목표 셀이 굵은 inset 테두리를 가진다.
- 소계와 행 합계의 목표 셀이 각각 표시된다.
- 구성 셀과 `not_tested` 결과에는 테두리가 생기지 않는다.

### 현금흐름표

- 각 자산 계열의 취득·처분, 차입 계열의 유입·유출, 리스 원금 상환을 검증한다.
- 비현금 조정이 정확히 차이를 설명하면 `explainable_gap`이 된다.
- 동률 후보와 금액이 아닌 필드에는 오검증을 생성하지 않는다.
- 현금흐름표 라인과 주석 근거 모두 정확한 원문 좌표를 가진다.
