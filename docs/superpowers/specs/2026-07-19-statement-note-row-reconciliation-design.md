# 재무제표 행별 주석 금액 대사 및 검토 드로워 설계

## 목적

재무제표 본문에서 주석번호가 표시된 모든 공시계정 행을 검증 대상으로 삼는다. 재무제표 행에 표시된 주석번호만을 탐색 범위로 사용하고, 해당 주석에서 계정과 기간이 맞는 금액을 찾아 재무제표 금액과 직접 비교한다. 결과는 사용자가 검증 내용과 후속작업을 즉시 이해할 수 있는 우측 드로워로 표시한다.

초기 계정 분류 결과에서는 SK이터닉스 연결 27행과 별도 27행만 포착됐지만, 원문 좌표 기준 재측정 결과 현금흐름표를 제외하고 연결 54행과 별도 52행이 주석번호를 표시한다. 현재 파이프라인에는 행별 주석 참조 대사 하네스가 없어 선택된 계정군만 대사되고 있다. 이 설계는 회사별 예외가 아니라 공통 의미 계층과 근거 좌표를 복원해 분류되지 않았던 행까지 포함한다.

## 검증 단위

검증 결과는 `재무제표 행 1개 = 대사 결과 1개`를 원칙으로 한다. `(주3,10,20)`처럼 여러 번호가 표시되어도 주석별로 카드를 분리하지 않는다.

- 금액 대사 주석: 재무제표 행과 같은 계정·기간의 직접 비교 금액을 제공한 주석
- 관련 공시 주석: 행에 표시되었지만 직접 금액 대사에는 사용되지 않은 주석
- 확인 필요 주석: 금액 후보가 없거나 복수 후보 때문에 비교 대상을 확정하지 못한 주석

주석번호가 표시되지 않은 행은 이번 기능이 임의로 주석을 추정하지 않는다. 별도의 공시 완전성 검사는 후속 기능으로 유지한다.

## 데이터 흐름

1. 의미 계층이 재무제표 표의 각 셀에서 `(주3)`, `(주3,8)`, `주석 12` 및 주석번호 전용 열을 추출한다.
2. 각 참조는 재무제표 행, 주석번호 셀, 표·행·열 원문 좌표를 보존한다.
3. 계정 분류 계층이 같은 행의 당기 금액, 계정 키, 금액 셀 좌표를 제공한다. 표준 계정으로 분류되지 않은 행도 원문 계정명과 금액 좌표를 보존해 검증 대상에서 제외하지 않는다.
4. 대사 하네스는 표시된 주석번호 범위 안에서만 주석 금액 후보를 수집한다.
5. 후보는 계정 문맥, 당기 여부, 기말·합계·잔액 역할, 분류 신뢰도로 순위를 정한다.
6. 단일 최상위 후보가 있으면 재무제표 금액과 주석 금액을 비교한다. 동순위 후보가 여러 개면 임의 선택하지 않는다.
7. 결과는 기존 `CheckResult`의 금액과 근거 필드를 사용하고, 근거 역할을 통해 드로워가 재무제표 원문·표시 주석번호·대사 금액·관련 주석을 구분한다.

Footing과 현금흐름 검증은 기존처럼 별도 하네스로 유지한다. 이번 하네스는 재무제표 본문과 표시 주석 사이의 금액 대사만 담당한다.

## 상태 판정

- 일치: 단일 대사 후보가 있고 차이가 허용오차 이내다.
- 불일치: 단일 대사 후보가 있으나 차이가 허용오차를 초과한다.
- 원문 확인 필요: 계정 문맥은 맞지만 후보가 복수이거나 표 구조·기간을 확정하지 못한다.
- 주석 금액 확인 필요: 표시 주석은 존재하지만 직접 비교할 금액을 찾지 못한다.
- 주석 참조 오류: 표시된 주석번호의 원문이 존재하지 않는다.

주석의 주제만 관련되어 있다는 이유로 금액 대사를 `일치` 처리하지 않는다. 관련 주제는 관련 공시 근거로만 표시한다.

## 드로워 정보 구조

드로워는 시스템 필드가 아니라 검토자의 판단 순서에 맞춰 구성한다.

1. 제목과 결론
   - `유형자산 · 일치`처럼 계정명과 결론을 가장 먼저 표시한다.
   - 현재 선택된 연결/별도 범위와 보고기간을 보조 정보로 표시한다.
2. 무엇을 대사했는지
   - `재무제표 유형자산 ↔ 주석 10 기말 장부금액`
   - 직접 금액을 제공한 주석번호와 주석 행 명칭을 명시한다.
3. 금액 비교
   - 재무제표 금액, 주석 금액, 차이를 세로로 표시한다.
   - 금액이 확정되지 않은 경우 `-` 대신 `금액 후보 확인 필요`처럼 이유가 드러나는 문구를 표시한다.
4. 사용한 주석
   - `금액 대사`와 `관련 공시`를 구분해 표시한다.
   - 여러 주석이 있더라도 한 계정 카드 안에서 역할을 확인할 수 있어야 한다.
5. 검증 설명
   - 어떤 범위와 기준으로 비교했는지 한 문장으로 설명한다.
6. 후속작업
   - 일치: `추가 조치가 필요하지 않습니다.`
   - 불일치: 양쪽 원문 금액·기간·공시 범위를 확인하고 차이 원인을 기록하도록 안내한다.
   - 후보 복수: 후보 주석 금액을 확인해 대사 대상을 확정하도록 안내한다.
   - 금액 미확인: 지정 주석에서 해당 계정의 합계·기말금액을 확인하도록 안내한다.
   - 주석 없음: 본문 주석번호와 실제 주석번호를 확인하도록 안내한다.
7. 원문 이동
   - `재무제표 원문 보기`와 `주석 원문 보기`를 분리한다.
   - 버튼은 정확한 표·행·열로 이동하고 해당 셀을 강조한다.

## 표시 규칙

- 재무제표 행 전체를 누르면 해당 행의 대사 카드가 열린다.
- 한 행에 다른 검증이 함께 있으면 드로워 탐색으로 결과를 이동하되, 행별 주석 대사를 우선 카드로 연다.
- 엔진의 계정 키, 상태 코드, 파싱 코드, 클래스명은 사용자에게 노출하지 않는다.
- 내부 근거가 없는 단정적 일치 문구를 사용하지 않는다.
- 연결/별도 전환 시 현재 범위의 결과만 드로워에서 탐색한다.

## 오류 처리와 안전장치

- 주석번호 추출 확대 시 `[주1]` 같은 페이지 표식과 `3,343,585주` 같은 주식 수량을 참조번호로 오인하지 않는다.
- 금액 후보가 복수이면 첫 후보를 선택하지 않고 원문 확인 필요로 판정한다.
- 재무제표와 주석의 단위 차이는 정규화된 원 단위 금액으로 비교하며 표시단위 반올림 허용오차를 적용한다.
- 모든 물적 금액 근거는 정확한 원문 셀 좌표를 보존한다.

## 테스트 및 완료 조건

- 주석번호와 당기 금액이 표시된 모든 재무제표 계정 행마다 계정 분류 성공 여부와 관계없이 정확히 하나의 행별 대사 결과가 생성된다.
- 별도 주석번호 열과 계정명 안의 주석번호를 모두 정확한 셀 좌표로 추출한다.
- 일치, 불일치, 후보 복수, 금액 없음, 주석 없음 사례를 각각 회귀 테스트한다.
- 복수 주석 중 직접 금액 주석과 관련 공시 주석이 구분된다.
- 드로워에 대사 대상, 세 금액, 사용한 주석, 상태별 후속작업, 양쪽 원문 이동이 표시된다.
- SK이터닉스의 주석번호 표시 비현금흐름 계정인 연결 54행과 별도 52행이 누락 없이 행 클릭 대사 결과를 갖는다.
- 기본 테스트 `uv run pytest`와 정적 검사를 통과하고, 생성된 웹 보고서를 실제 브라우저에서 연결/별도 각각 QA한다.

## 범위 제외

- 재무제표에 표시되지 않은 주석을 추정해 자동 연결하는 기능
- 공시 누락 자체에 대한 감사 결론
- React 또는 Next.js 도입
- Footing 또는 현금흐름 대사 엔진의 책임 통합
